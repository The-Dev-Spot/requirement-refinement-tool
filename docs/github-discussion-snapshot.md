# Original GitHub discussion integrity

An uncited comment may supersede an earlier decision without changing the
quoted excerpt or the issue timestamp used by a prior review. Freshness must
compare the discussion originally collected with the discussion observed now.

## Collection and binding

The GitHub-only collector can emit **v3 evidence** and a separate, private
authenticated original discussion snapshot. The collection plan remains v2;
all selected issues must enable `include_comments: true`. The existing limits
remain: 20 comments per issue, 120 KB rendered discussion per issue, explicit
repository/source selection and bounded excerpts. Exceeding a limit fails;
the collector does not silently paginate or truncate the discussion digest.

The digest uses a canonical structured record containing issue identity,
title, body, revision, state, and each comment's identity, author, revision and
body. It does not hash the concatenated display excerpt: a body containing
comment-like delimiters cannot impersonate a real comment record. The existing
rendered excerpt remains the only source text supplied to models.

The snapshot stores hashes and source metadata, never full discussion text.
A separate domain-separated HMAC authenticates its exact binding to the v3
evidence, target, scope, story and policy. The **digest of the ordered original
discussion records is also inside the v3 evidence itself**. The original review,
preview, research and challenge therefore bind it through the existing evidence
hashes. Recollecting an edited discussion changes the evidence hash even if all
excerpts and timestamps remain identical; old reviews cannot be reused.

Initial reads are rechecked before output. A changed original discussion cannot
receive a valid snapshot. Files use exclusive creation and mode 0600. If one
of the two file writes fails, the invocation fails; a partial pair cannot pass
trusted reconciliation and must not be treated as a completed collection.

## Recheck and reconciliation

For v3 evidence, the collector authenticates the original snapshot **before**
loading the GitHub token or making a request. It then reads each complete bounded
discussion again and compares structured hashes with the original, followed by
a second read for changes during checking. Edited/deleted/added comments,
comment identity/author/revision changes and issue state changes invalidate the
snapshot even when the pinned excerpt and issue `updated_at` match.

The signed freshness readback records the original snapshot receipt digest and
per-issue claimed/observed discussion digests. Trusted reconciliation requires
v3 evidence, authenticated original snapshot, version-2 freshness readback,
complete matching source/discussion coverage and the existing freshness age
limit. Its own report is now version 2. Old excerpt-only v2 evidence and
version-1 freshness readbacks remain usable for diagnostics but **cannot pass
trusted reconciliation**. Recollect and re-review; do not upgrade an old packet
or mint an original snapshot after the review.

This establishes snapshot integrity at read time. It does not establish that
the model saw or understood every uncited comment, that research was exhaustive,
that a supersession is valid policy, or that an authorized owner approved it.
Deleted content before the original collection, edit histories, attachments,
reactions and GitHub timeline events are not captured. All question resolutions,
approval, Inbox import and Forge dispatch remain blocked.

## Future authorized collection example (not deployed)

~~~sh
python3 scripts/collect_github_context.py \
  --plan /private/selection.json \
  --story /private/story.json --policy /private/policy.json \
  --github-key-file /private/secrets/github-read.key \
  --attestation-key-file /private/secrets/collector-attestation.key \
  --output /private/github-v3-unique.json \
  --snapshot-output /private/original-discussions-unique.json
~~~

The existing random-secret provisioning and isolation requirements apply: only
trusted collector/reconciler processes hold the symmetric attestation key.
No key is installed or generated by this change. No model receives a token,
attestation secret or full discussion. GitHub Issues remain the only actionable
intake; Linear history remains a separate optional read-only context packet.
See [reconciliation](question-evidence-reconciliation.md) for the later commands.
